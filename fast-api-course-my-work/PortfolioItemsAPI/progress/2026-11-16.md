- Pregledana je postojeća `fast-api-course-my-work/Project 3` baza **read-only**. Ima tabelu `todos` sa kolonama `id`, `title`, `description`, `priority` i `complete`.

- Razgovarali smo o `nullable`: u TodoApp-u API schema zahteva `priority`, ali model baze dopušta `NULL`. Za novi projekat odluku o obaveznosti treba doneti prema domenskim pravilima i sprovesti je i u bazi, ne samo u API validaciji. To u praksi znači da se obavezna polja moraju označiti sa `nullable=False` u SQLAlchemy modelu i odgovarajuće validirati u Pydantic šemi.

- `PortfolioItemsAPI/models.py` je popunjen minimalnim ORM modelima. U `Items`, `description` je opcion (`nullable=True`); cena, status, datumi, vlasnik i kategorija su obavezni. Ova pravila se reflektuju i u bazi (`nullable=False`) i u API šemi, kako bi se obezbedila konzistentnost.

- `created_at` koristi `server_default=func.now()`. Ovo obezbeđuje da baza automatski postavi vreme kreiranja reda.

- `updated_at` koristi i `server_default=func.now()` i `onupdate=func.now()`.

- `Items.status` je sada ograničen na `draft`/`published` enum vrednosti, umesto Boolean vrednosti.

## Šta je naučeno / razjašnjeno

- Projekat je organizovan po odgovornostima (`api`, `db`, `models`,`schemas`); skeleton se implementira postepeno i još nema API endpoint-e.

- ORM modeli i Pydantic šeme imaju različite odgovornosti: ORM mapira tabele, Pydantic validira API ulaz/izlaz.

- `nullable=False` sprečava `NULL`, ali ne proverava npr. prazan tekst, negativnu cenu ili format email-a. Takva pravila zahtevaju odgovarajuću validaciju i/ili `CHECK`/`UNIQUE` constraint-e.

- `server_default=func.now()` traži od baze podrazumevano vreme pri kreiranju reda. `onupdate=func.now()` je SQLAlchemy ponašanje za ORM izmene, a nije SQLite trigger; direktan `sqlite3 UPDATE` sam po sebi neće ažurirati kolonu `updated_at`.

- `func.now()` pravi SQL izraz preko SQLAlchemy `func` namespace-a. Nije isto što i Python `datetime.now()`. Razlika je u tome što `func.now()` generiše SQL izraz koji baza izvršava, dok `datetime.now()` generiše trenutni datum i vreme u Python-u. Ovo znači da `func.now()` uvek koristi vreme baze, dok `datetime.now()` koristi vreme servera na kojem se izvršava Python kod. Nas zanima vreme baze, jer želimo da `created_at` i `updated_at` budu konzistentni sa vremenom baze, a ne sa vremenom servera zbog mogućih razlika u vremenskim zonama i tačnosti. Važno je razumeti ovu razliku kako bi se izbegli problemi sa sinhronizacijom vremena između aplikacije i baze.

- Python `datetime` je tip vrednosti, a SQLAlchemy `DateTime` je tip kolone. `FastAPI/Pydantic` često parsiraju/serijalizuju datume u ISO 8601 obliku. Ovo znači da se datumi u JSON-u obično pojavljuju kao stringovi u formatu `"YYYY-MM-DDTHH:MM:SS"`.

- Python `Decimal` je pogodniji od `float` za cene. Koristi se zajedno sa `Numeric(10, 2)` u modelu i `Decimal` poljem u API šemi. SQLite nema istu fiksno-decimalnu garanciju kao PostgreSQL, pa preciznost treba proveriti. Za striktne finansijske sisteme može se čuvati broj centi kao integer.

- `ItemStatus` je `str, Enum`, pa vrednosti mogu prirodno raditi sa tekstom i Pydantic-om. SQLAlchemy `Enum` je podešen da čuva lowercase `.value` (`draft`, `published`) i da napravi SQLite `CHECK` ograničenje.

- Enum ima `default=ItemStatus.DRAFT` za ORM insert i `server_default="draft"` za podrazumevanu vrednost na DB strani.

- `SQLAlchemy Enum` na SQLite-u se koristi kao tekstualna kolona uz CHECK ograničenje, jer SQLite nema namenski native enum tip.

## Provere i granice

- Modeli su provereni u izolovanoj in-memory SQLite bazi (`sqlite:///:memory:`): registrovane su tabele `users`, `categories` i `items`.

- ORM insert je dobio `draft` kao default, datumi su popunjeni pomoću `func.now()`, a `Decimal("12.30")` je sačuvan/pročitan kao `12.30`.

- Poseban `INSERT` direktnim SQL-om, bez statusa i datuma, dobio je `draft`, `created_at` i `updated_at` iz DB `server_default` vrednosti.

- SQLite je odbio status `archived` sa `IntegrityError`; potvrđen je generisani CHECK constraint koji dozvoljava `draft` i `published`.

- Pydantic 2 proverom potvrđeno je da string `"19.99"` postaje Python `Decimal("19.99")`, a JSON serijalizacija vraća `"price":"19.99"`.

- Sve runtime provere su koristile in-memory bazu, ne projektni `.db` fajl.

- Provereno je da SQLite konekcija u toj izolovanoj proveri ima `PRAGMA foreign_keys=0`; strani ključevi nisu automatski aktivni u tom testu, pa njihovo sprovođenje ostaje zasebna konfiguraciona tema.

- Potvrđeno je da postojeći Project 3 `todos` model dozvoljava `NULL` za `priority`, iako Pydantic request schema očekuje obaveznu vrednost.

- Nisu implementirani API endpoint-i niti pokrenuti njihovi testovi.

- `portfolioitemsapp.db` još nije kreirana. Pre prvog pokretanja treba proveriti da postoji `PortfolioItemsAPI/data/`.
